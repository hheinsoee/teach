# Pass Rubric

**Shipping working code is not a pass.** All six criteria required.

| # | Criteria | How it's checked | Agent can fake it? |
|---|---|---|---|
| 1 | Live app: frontend + backend + database + auth | Open the URL | yes |
| 2 | Open any file **the student asked the agent to write** and explain it | Random file, oral | **no** |
| 3 | Read an error and locate the problem **without the agent** | Live exercise | **no** |
| 4 | Find what is wrong or unnecessary in agent-generated code | Flawed sample given | **no** |
| 5 | Prove a protected endpoint is protected | Live exercise | yes |
| 6 | Defend the shape of the data model | Oral | partly |

## Scope of criterion 2

Application code only — files the student requested.

**Excluded:** framework scaffolding, generated config, `node_modules`, library internals,
anything under `node_modules/`, migration files generated by a tool.

Nobody can explain all of that. Including it makes the rubric unenforceable, and an
unenforceable rubric gets silently dropped the first time it is inconvenient.

## How to run criterion 2

1. Open the student's repository.
2. Pick a file they wrote — `app/api/expenses/route.ts` is usually the best one.
3. Point at a random block of 5–15 lines.
4. Ask: *"What does this do, and what breaks if I delete it?"*

Pass = they explain the intent and a consequence. They do not need to recall syntax names.
Fail = they read the code aloud without explaining it, or they say "the agent wrote that".

## How to run criterion 3

Break their app yourself before the day:

- rename an environment variable
- change a column name in one query
- return the wrong status code
- remove an `await`

Give them the error. **No agent.** 10 minutes.
Pass = they name the file and the likely cause. Fixing it is not required.

## How to run criterion 4

Hand them a working-looking snippet containing one real problem. Rotate between:

| Flaw | What they should notice |
|---|---|
| Query missing `where user_id = ?` | Anyone can read anyone's data |
| String-concatenated SQL | SQL injection |
| `catch (e) {}` swallowing an error | Failures become invisible |
| Four layers of abstraction for one function | Over-engineering |
| An API that does not exist | The agent hallucinated |

Pass = they find it, or they correctly say "I would not merge this until I understood X".
